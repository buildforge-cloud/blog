## CI gets the test browser without apt-get (blog#85)

`npx playwright install --with-deps chromium` in `ci.yml` runs apt-get, and a
dead apt mirror hung it 3 times on 2026-11-11 (decision 3428). The 3rd time,
run 43039293425, the job's 8-minute bound cancelled it, which held blog#84.

Picked the cache over the Playwright container. The container would run the
whole job in it, and the font-block step needs `sudo` and the runner's own
`/etc/hosts`, so that step would change. It is also a large image to pull
from another outside server on every run.

Now `ci.yml` reads the runner image (`$ImageOS`, such as `ubuntu24`) and the
`@playwright/test` version from `package-lock.json`, and restores
`~/.cache/ms-playwright` with `actions/cache/restore` keyed on both. It runs
`--with-deps` only on a miss, then saves with `actions/cache/save`. On a hit
nothing is installed: the `ubuntu-latest` image already has Chrome, so
Chromium's libraries are there. The image is in the key because a hit trusts
it; a new image misses once and gets the libraries from apt-get. Restore,
install and save each have `timeout-minutes: 3`, so a hang names its step.
The restore and the save have `continue-on-error`: a stalled restore falls
through to the install, and a failed save does not fail the run. The save is
a step, not `actions/cache`'s post-job step, because a post step cannot take
a bound. `${{ env.ImageOS }}` would not work: the `env` context holds only the
workflow's own variables, so the image is read in a shell step.

A pull request's cache is visible only to that pull request. Before this,
every cache in the repo sat under `refs/pull/N/merge`, so each new PR started
cold. `ci.yml` now also runs on a push to `main`: its cache is visible to every
PR. `tests/workflows.test.mjs` pins all of this.

GitHub evicts a cache nobody has read for 7 days. A PR that restores `main`'s
cache keeps it alive; after a quiet week the next push to `main` saves it again.
