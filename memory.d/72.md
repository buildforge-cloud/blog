Workers may not link anything outside their worktree into it, so they test a
scratch copy of the blog with `node_modules` symlinked from the main checkout.
`node --test`, `npm run lint` and `npm run format:check` work that way.
`npm run build` does not: Astro resolves the link to its real path and fails
with `No cached compile metadata found for ".../node_modules/astro/components/ClientRouter.astro?astro&type=style..."`.
A real copy (`cp -a`, about 450 MB, fine on `/tmp`) builds (measured
2026-10-31, blog#72).

**Why:** the error names an Astro component, not the link, so it reads like a
broken post or package and costs turns.

**How to apply:** in a blog scratch copy, symlink `node_modules` for tests,
and copy it before any `npm run build`. Related: [[blog-worktree-node-modules]].
