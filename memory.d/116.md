Two Dependabot gotchas met in blog#116 (2026-11-20), true for every repo with
a `.github/dependabot.yml`:

- An `ignore` rule holds back security updates too, not only the monthly
  version updates. The blog ignores astro 7.2.10 and later while
  `@astrojs/mdx` is on 7 (blog#83), so an astro security fix gets no PR there.

- A Dockerfile tag that names a major only (`node:22-alpine`) lets the docker
  entry offer only the newest major, and 23 and 25 are odd, non-LTS Current
  releases. The blog's docker entry ignores those two by range
  (`">= 25, < 26"`). From 27 on, Node ships one major a year and each one
  becomes LTS (nodejs.org, "Evolving the Node.js Release Schedule", Stefan's
  correction on blog#116), so no later major is ignored.

**Why:** both look safe in the file and fail quietly: a missing security PR,
or a merged non-LTS runtime.

**How to apply:** when you add an `ignore`, say in its comment that security
fixes for those versions are moved by hand. Never extend the odd-node list
past 25.
