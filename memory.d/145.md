satori 0.63 (blog#145, Nov 2026) renders like a browser, where 0.26 did not:
a `position: absolute` or `opacity < 1` box is painted after the in-flow
boxes, boxes are content-box (the border and padding sit outside the width),
and a `<p>` gets a 1em margin. AstroPaper's OG template (an absolute,
0.9-opacity shadow box before the card) then paints the shadow over the card
and cuts a four-line title. `astro build` and every check stayed green, and
only the PNG pixels showed it. The fix: `position: relative` on the card,
`boxSizing: border-box` on both boxes, and an explicit `<p>` margin. Any
fleet repo on an AstroPaper-style OG template needs the same before taking
satori past 0.26. Assert on the built PNG (ink in the card, the card's edge
row), as blog's `tests/og-image-render.spec.mjs` does.

**Why:** a satori bump went through Dependabot as a "minor" (0.26 → 0.63, a
0.x minor) and broke every share image without a failing check.

**How to apply:** when a satori bump is offered, render the OG images and
read them (or run the pixel spec) before merging. A green build proves
nothing about the images.
