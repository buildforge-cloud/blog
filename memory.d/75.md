A blog worker can run `agent-orchestrator/sanitize.py <file>` on a post, and
it answers `clean (0 block-list words loaded)`. The private block list of
container and customer names, `~/.claude/orchestrator-denylist.txt`, is not
in the worker's home, so that run checks only secret shapes, private IPs,
server paths and internal hosts (measured 2026-10-31, blog#75). The
executive's own run, with the list, is the real gate.

**Why:** "clean" reads as a full pass, and a PR body that says only "clean"
claims a check that did not run.

**How to apply:** quote the whole line, block-list count included, in the PR
body. Also check the post by hand for container, host and people's names,
and leave the full check to the executive's review.
