**astro is pinned to exactly 7.2.9 for now (blog#83).** astro 7.2.10 and later
want `@astrojs/markdown-remark` ^7.3, and every `@astrojs/mdx` 7.x pins 7.2.x,
so a newer astro needs `@astrojs/mdx` 8, a major update. With a `^` range,
`npm update` and `npm audit fix` reach for the newest astro and stop with
ERESOLVE, and nothing else in that run is updated. Never use `--force`.
`tests/packages.test.mjs` (in `npm test`) fails while mdx is on 7 and astro is
a range or 7.2.10 or later. It also fails when the lockfile holds a copy of a
package in a range a known advisory names, nested copies included: when a new
critical or high alert is fixed, add its package, range start and fixed
version there.
