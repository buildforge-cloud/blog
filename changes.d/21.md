# Issue #21 -- for CLAUDE.md

Target: `AGENTS.md` (`CLAUDE.md` is a symlink to it). Three edits.

1. Section "Deployment": replace the whole paragraph that starts
   "⚠️ **No page gets `nginx.conf`'s security headers.**" (it is no longer
   true) with:

       ⚠️ **No `location` in `nginx.conf` may call `add_header`.** nginx drops
       a level's `add_header` lines in any block that sets one of its own, so
       until blog#21 no page got the CSP, the Referrer-Policy or HSTS. Now two
       `map`s pick `Cache-Control` and `Pragma` by path, and only the
       `server` level sends headers. A new cache rule is a map line (plus an
       `expires` in its location). `npm test` fails on a block that drops a
       header (`tests/check_nginx_headers.py`, a pinned shared part).

       ⚠️ **The CSP runs no inline script.** Write a page script as a bundled
       `<script>` that does its work on `astro:page-load` (a module runs once
       per visit), never `is:inline` or `define:vars`. JSON-LD is data and is
       fine. `astro.config.ts` stops Astro from inlining a small bundled
       script. `npm run test:pages` opens every page under `nginx.conf`'s CSP
       and fails on any violation. Run `NGINX_RIG=1 npm run test:pages` after
       a change to `nginx.conf` or the CSP: only then do a real nginx send the
       headers and giscus load (CI blocks giscus.app). Evidence in
       `docs/ENGINEERING_LOG.md` (blog#21).

2. Section "Comments (giscus)": replace the last two sentences of the
   paragraph about the vanilla-JS embed ("It still needs the
   `data-astro-rerun` attribute ... unless marked to re-run.") with:

       `Comments.astro` is a bundled module that mounts giscus on each
       `astro:page-load` (blog#21). Its old `is:inline define:vars` script lost
       `data-astro-rerun` to `define:vars`, so a post reached from another
       post by a link had no comments.

3. The "Shared parts (blog#19)" paragraph: add `tests/check_nginx_headers.py`
   to the list of pinned parts.

Keep each to about this length.
